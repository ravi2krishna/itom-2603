-----------

    -> Credentials 

        -> Once Mid Server Reaches The Devices On Network, it needs to login into 
        System and pull the information from it. 

        -> To Pull the information we need Credentials i.e Authentication Secrets 

        -> Credentials Live in discovery_credentials Table 
        
        -> NOTE: All the Credentials we use are encrypted 

        -> We Have Different Types Of Credentials 

            -> Windows Uses Username & Password, pass Credentials as username & password 

            -> Unix Like Systems i.e Linux Machines, they typically use 
            Password less Authentication i.e SSH Key Pairs 

                -> Public Key & Private Key  

            -> If You have VMWare Environment, use VMware Credentials

            -> API Keys which are typically used for Cloud Environments 


    
    -> Probes & Sensors

        -> Probes & Sensors are two halves of same job. 

    -> Probes 

        -> A Probe is like a Question 

            -> It can be a command or it can be a script that MID Server executes 
            against your target device(Windows Machine, Linux Server, NIC, Disk etc) 

            -> Probes runs on MID Server Side, Reaches target device and brings back all 
            the raw output like Commands, JSON, WMI Queries etc 

            -> The RAW output will be stored at ServiceNow using ECC Queue 


    -> Sensors 

        -> A Sensor is like a Answer  

        -> It's a Script That Takes Raw output and starts parsing it and extracts 
        fields like OS, IP, Processes, Ports etc and maps them to CI Attributes, 
        which inturn gets Updated as a record in CMDB

    -> Patterns 

        -> Patterns are ServiceNow's Modern Replacement for Probes approach 
        for Application and Software Discovery. 

        -> Probes are Still Heavily used for Infrastructure (Hardware/CPU/RAM/NW)

        -> NOTE: Patterns are preferred method for discovering Applications & Services 

        -> A Pattern is a declarative definition unlike imperative definition of probes, 
        used to discover specific type of softwares and services, it defines 
        what to look for, which pattern to run and what files to read and how to 
        map the results to CI Attributes. 

        -> Patterns are available in Visual Designer(Pattern Designer), rather than
        working with javascript. 

        -> Patter has Identification Section, which defines how to process 
        applications or services.

    -> Discovery Schedule

        -> A Discovery Schedule is the Configuration Record that defines a discovery run.
        It Answers 
            -> what should be scanned 
            -> When Should it run 
            -> Which Mid Server To Use 

        -> Key Field On Discovery Schedule Includes IP Ranges (ex 10.0.0.0/24) or

        -> Schedule can be On demand(your choice) or daily / weekly / monthly etc 

        -> Select Mid Server To Use 

        -> NOTE: When Schedule Fires, it creates Discovery Status (DS001090) 

            -> Each Status Contains Discovery Logs (Debugging Tool)

                -> Contains Every Step like which IP was tried, which probe was executed, 
                which sensor was executed, which pattern was executed, which CI created etc 


    -> CI Classification

        -> CI Classification is the Final Step

        -> Classifier Engine / Decision Engine Determines What CI Class To Create and 
        Whether To Create a new CI or Update an Existing CI 

        -> When a Sensor Finishes Parsing Data from a device, it hands set of raw attributes 
        to CI Classifier Engine, the Classifier's job is look at the attributes and answer
        two questions 

            -> What Type Of CI is it ?? 

            -> Does It Already Exist in CMDB ?? 

        -> NOTE: CI Classifier Engine == Identification Rules 

        -> NOTE: When discovery finishes Scanning a device, IRE Looks through this list to find 
        the matching rules for data it collected. 

            -> https://dev407423.service-now.com/cmdb_identifier_list.do (link)


    -> IRE (Identification & Reconciliation Engine)

        -> IRE is the underlying servicenow Engine that uses identifier rules(link)

        -> Each CI Class has a defined set of identifier fields which makes CI's Unique 

        -> Criterion Attributes are like Unique fingerprints Of CI 

        -> For Example, Web Server Like Apache has combination of 
        System class + version + config file might be the identifier 

        -> NOTE: If IRE finds a match, it updates Existing CI, this is called Reconciliation.
        Whereas if no match was found, it creates a new CI. 

    
    -> Simple Analogy 

        -> Taking Hospital Analogy 

            -> Patient Walks In (Discovery Finds a Device)

                -> Receptionist asks: Have You Been Here Before ?? 

                    -> Yes: Pulls Existing File, Updates New Info (Reconciliation) 

                    -> No: Creates New Patient File (Create New CI)


        -> ITOM Perspective 

            -> Question 1 : What are you ?? 

                -> Linux Server ? / Widows ? / Application ? 

            -> Question 2 : Have i seen you before ?
                (Does this CI Already Exist in CMDB)

                -> Yes: Update Existing CI 

                -> No: Create New CI

            -> What Type is this CI ?? <----- CI Classification 

            -> Does this CI Already Exist ? <------ Identification 

                    Yes                 No

    -> In Cloud Datacenters We Have 

        -> Availability Zones 

            -> An Availability Zone (AZ) in AWS is one or more discrete 
            data centers with independent power, cooling, and 
            networking within an AWS.

        -> Subnets 

            -> A subnet in AWS is a smaller segment of a 
            Virtual Private Cloud (VPC) "IP address range" 
            where you can place groups of isolated cloud 
            resources like virtual servers. 

        -> NOTE: Within Availability Zones We Got Subnets. 

        -> NOTE: When Creating Subnets, make sure you create them
        in the Network where Mid Server is Installed. 

        -> When Creating Subnet, We Must Provide Subnet CIDR block 

            (CIDR - Classless Inter Domain Routing)

        -> Subnet Calculation is done based on CIDR 

            -> An Network Address (IP Address) is 32 Bit Number 

            -> 32 Bits Means 4 Octets and Each Octet is 8 Bits 

            -> An IP Address 10.0.0.0 (A.B.C.D)

            -> NetMask(Network Mask) Helps You Define Size 

            -> NOTE: When Doing Discovery In Previous Lab 
            We have given 32 as Network Mask, which means 
            only One Device. 

            -> If we say Network Mask as 20, it means 4k(4096) Devices

            -> If we say Network Mask as 21, it means 2k(2048) Devices

            -> If we say Network Mask as 24, it means 256 Devices

            -> 10.0.0.0/32 Means One Device 

            -> 10.0.0.0/24 Means 256 Devices 

            -> 10.0.0.0/20 Means 4096 Devices 

        -> Formula 

            -> Result = Total Network Bits - Your NetMask 
            -> Number Of Devices / IP's = 2 ^ Result 

            /22 - Result = 32 - 22 = 10 --> Number Of Devices / IP's = 2 ^ 10 = 1024 
            /20 - Result = 32 - 20 = 12 --> Number Of Devices / IP's = 2 ^ 12 = 4096
            /24 - Result = 32 - 24 =  8 --> Number Of Devices / IP's = 2 ^  8 = 256
            /32 - Result = 32 - 32 =  0 --> Number Of Devices / IP's = 2 ^  0 = 1

            /28 - Result = 32 - 28 =  4 --> Number Of Devices / IP's = 2 ^  4 = 16

    -> Service Mapping 

        -> Service mapping is used to discover and track IT applications and 
        components in an organization, outlining how each connects to business services.

        -> Service mapping charts a company’s interconnected IT environment. 
        This allows organizations to build a service-aware view of 
        how their underlying IT applications and related components 
        connect to business services.

        -> https://media.licdn.com/dms/image/v2/D5612AQFTabVd6lwPNw/article-cover_image-shrink_600_2000/article-cover_image-shrink_600_2000/0/1675397958842?e=2147483647&v=beta&t=yN3OPRI6JCxvBOLTsW72W3ZQpjN1uDWIztrEgpI-FrU

        -> NOTE: Service mapping is a way of more clearly understanding application services.

    -> Application Service 

        -> An application service is defined as a group of connected applications 
        and hosts configured to operate together, to provide a specific service 
        to an organization or end-user.

        -> One example of an application service is financial reporting. 
        When an organization needs to generate a financial report, 
        they employ an application service that includes computer hardware, 
        web server, application server, databases, middleware, and 
        network infrastructure components. 
        Each of these works together to provide the service of 
        creating the desired financial report.

        -> Traditionally, IT departments have relied on horizontal discovery to map 
        IT infrastructures. This delivery method creates inventories that act as 
        though every application and device is standalone, without making note of 
        the connections between devices and application services. 
        
        -> Service mapping forgoes this outdated approach, relying instead on 
        top-down mapping that focuses on the connections between devices and applications 
        so that any issues or changes can be immediately identified along with their impact 
        on the rest of the application service.

    -> How Service Mapping Works 

        -> Correctly implemented, service mapping creates a detailed, complete view of objects 
        within the IT infrastructure, with a focus on the semantic connections between them. 
        To do this, service mapping deploys different methods for identifying 
        application services. One widely-used approach is through locating patterns. 
        
        -> In service mapping, patterns are sequences of operations used to 
        detect attributes of devices and applications along with their outbound connections. 
        Asset management tags, for example, can help clearly identify relationships 
        between applications and are valuable in mapping application services.

        -> Additionally, service mapping may also be able to trace traffic 
        as it moves between applications and devices (called traffic-based mapping).

       -> https://www.servicenow.com/docs/r/zurich/it-operations-management/service-mapping/service-mapping-get-started.html
